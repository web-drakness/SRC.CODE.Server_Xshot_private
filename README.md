## โปรเจกต์นี้คืออะไร

การสร้างใหม่ (clean-room reimplementation) ของส่วนหลังบ้านเครือข่าย/บัญชี
ที่จำเป็นต่อการรันเกมยิงออนไลน์รุ่นเก่า **แบบโลคอล** เพื่อการศึกษาและอนุรักษ์
ประกอบด้วย:

- **เซิร์ฟเวอร์เกม/handshake (TCP)** ที่พูดพรอโตคอลไบนารีแบบเดิม
- **บริการ HTTP bootstrap/patch** ที่เสิร์ฟคอนฟิก/แมนนิเฟสต์ชิ้นเล็ก ๆ ที่ตัว launcher เรียกขอ
- **REST API + ฐานข้อมูลโลคอล** สำหรับบัญชี ตัวละคร และ session
- **เครื่องมือวิเคราะห์** ที่ใช้ reverse-engineer การจัดเฟรมพรอโตคอล แคตตาล็อกข้อความ
  และฟอร์แมตคอนเทนเนอร์ของไฟล์แพ็กเกจ (ที่มีเอกสารอธิบายไว้)

## โปรเจกต์นี้ **ไม่ใช่** อะไร

- ❌ ไม่ใช่สำเนาเกมเถื่อน และไม่แจกเกม
- ❌ ไม่ใช่ "โปรโกง" (cheat), "aimbot", "บายพาส anti-cheat" หรือแฮ็กเซิร์ฟเวอร์ออนไลน์
- ❌ ไม่ใช่วิธีเล่นบนเซิร์ฟเวอร์ทางการจริง หรือโจมตีเซิร์ฟเวอร์เหล่านั้น
- ❌ ไม่มีความเกี่ยวข้องกับผู้ถือสิทธิ์

เซิร์ฟเวอร์เกมของเกมนี้ **ออฟไลน์อยู่แล้ว** จึงไม่มีบริการจริงให้ไปก้าวก่าย
เป้าหมายคือการอนุรักษ์มรดกซอฟต์แวร์ชิ้นหนึ่ง และจัดทำเอกสารพรอโตคอลไบนารี
ที่เป็นกรรมสิทธิ์แต่เลิกใช้แล้ว เพื่อการเรียนรู้เท่านั้น

## สิ่งที่ต้องมี

- Windows (ไคลเอนต์เป็น Windows-only) — แต่ **ตัวเซิร์ฟเวอร์** รันได้ทุกที่ที่ Python รันได้
- Python **3.10+**
- สำเนาไคลเอนต์เกมที่ได้มา **อย่างถูกกฎหมาย** (ไม่รวมอยู่ในรีโป)
- ทางเลือก: เครื่องมือวิเคราะห์ใช้ไลบรารี RE ทั่วไป (ดู `tools/requirements.txt`)

## เริ่มใช้งานอย่างเร็ว

```powershell
# 1) เริ่มเซิร์ฟเวอร์โลคอล (HTTP :8080 + เกม :7451)
python server\run_server.py

# 2) ดู log ของเซิร์ฟเวอร์
Get-Content server\logs\server.log -Wait
```

คอนฟิกอยู่ที่ `server/config.json` (bind host/พอร์ต, โหมด, ชื่อ region, บัญชี seed)
เซิร์ฟเวอร์จะสร้างบัญชีโลคอลเริ่มต้นให้ตอนรันครั้งแรก — **ให้เปลี่ยนค่า seed
ในสำเนาของคุณเอง** และห้ามเผยแพร่ credential จริง

> ชี้ไคลเอนต์ของคุณเองมาที่ `127.0.0.1` ด้วยคีย์คอนฟิกตามที่เอกสารระบุ
> ห้าม commit `config.json` ที่มีค่าจริง, แพ็กเก็ตที่ดักได้ หรือคีย์ ขึ้นรีโป

## ทำงานอย่างไร (ภาพรวม)

1. ตัว launcher ขอ region/คอนฟิก + แมนนิเฟสต์เวอร์ชันจาก HTTP endpoint
2. มันตรวจไฟล์ของตัวเองเทียบกับแมนนิเฟสต์ (ขนาด/เช็กซัม)
3. มันเปิดตัวเกม ซึ่งจะเปิดการเชื่อมต่อ TCP ไปยัง host ที่ตั้งไว้
4. เซิร์ฟเวอร์ทำ handshake แบบเดิม แล้วแลกข้อความแบบมีเฟรม
   (login → ค้นหาบัญชี → session) แคตตาล็อกข้อความและการจัดเฟรมอยู่ใน
   [`docs/PROTOCOL.md`](docs/PROTOCOL.md) ซึ่งวิเคราะห์จากสำเนาของผู้ใช้เอง

บันทึกการ reverse-engineering ทั้งหมดอธิบาย *ฟอร์แมตและการจัดเฟรม* ไม่ใช่การแจกจ่าย
เนื้อหา และจัดทำเพื่อการทำงานร่วมกัน (interoperability) และการศึกษา
